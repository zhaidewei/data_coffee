# 活动详情：一张纵向流程图

读者：活动参与者、发布者，以及负责验收页面的人员。

## 页面目标

用户沿着一条线了解活动、完成参与，并看懂条件如何决定结果。主题、时间地点、报名、资源和规则位于流程对应节点，避免在多块面板之间查找和拼接信息。

## 信息与操作对应

| 流程节点 | 就地展示与操作 |
|---|---|
| 发起主题 | 标题、介绍、当前活动状态；发布者编辑或发布 |
| 时间与地点 | 荷兰当地时间、城市、场地要求、可见地址；提交和审核场地 |
| 参与报名 | 当前/最低/最多人数、本人状态、报名或退出、候补位置；名单可展开 |
| 补齐资源 | 分享、协办、现场负责人、物资与赞助意向；对应申请和审批 |
| 征集截止判断 | 截止时间、各条件是否满足；满足成团，不足取消 |
| 成团后维护 | 退出先递补，仍缺人或持续资源缺失则倒计时；补齐继续，否则取消 |
| 相聚与记录 | 举办/终态、实际取消原因、评估和介绍修订历史 |

规则随对应节点出现，不再单列“活动规则”面板。页面保持一条连续纵向连接线；分支仅用于真实的条件判断。报名和资源征集可以同时进行，纵向展示不应暗示必须先提供场地才能报名。

## 时间、地点偏好

用户提出新增偏好选择。现有活动发布后时间锁定，场地通过提案与审核确认。偏好属于发布前投票还是发布后参考意见，正在澄清；在规则明确前不展示无法保存或会误导用户的投票控件。

## 验收重点

桌面与手机均为同一条流程，无侧栏重复报名区，无另一张摘要流程图。原有权限、真实状态、截止时刻与倒计时保持；低频信息展开查看。所有可见操作仍调用真实接口，不能因重新排版而遗漏资源审核、退出、人工取消或历史记录。
