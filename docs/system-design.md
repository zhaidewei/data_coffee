# Data Coffee MVP 实现设计

读者：开发与验收人员。2026-09-05，实施版本。以 requirements-mvp.md v0.3 的最新有效决定为准。

## 运行与数据

当前应用位于 `app/`，独立使用 Workers 构建与 D1 迁移。旧 Vercel MCP 代码入口已退休，旧数据库保留且不迁移至当前应用。浏览器静态页面与 API 同源，邮箱验证码会话、DeepSeek 调用及所有写权限在 Worker 内执行。定时任务每分钟检查到期活动和待发送邮件；页面自行显示秒级倒计时，后台不承诺秒级结算。

为降低首版动态事务复杂度，每场活动保存为一份有版本的 D1 JSON 聚合：包含锁定规则、个人报名、申请、异常及评估回执。写入采用版本比较更新（CAS），冲突重新加载计算；活动更新、审计及通知插入在 D1 batch 事务内，以本次唯一提交标记约束副作用。不同活动独立竞争。用户身份和邮件队列独立表。适用少量活动和700成员，后续增长可迁移为拆表；本版需通过并发抢名额测试以及CPU/文档大小实测。

每次成员写操作先结算此前到期状态，再应用本次命令。截止时间采用服务器时间：有效时刻严格早于征集截止的变更属于征集；时间相等或更晚先结算。Cron与写请求调用同一规则函数，并发时只能提交一版，因此执行晚了也不会把晚到的资源计入原成团判断。客户端不能提供生效时间。

## 状态与时间

活动状态：draft → recruiting → confirmed / cancelled；confirmed ↔ repairing；有效活动结束后 completed。cancelled 和 completed 为终态。业务操作、版本及原因保留审计。

人数在成团后持续保持发布时的原最低门槛。退出先按申请顺序递补候补并通知；不足才启动独立的人数异常。场地、分享、协办、现场负责人按配置检查；每个缺口保留自己的deadline。人数或某个资源补齐仅解除对应异常，不刷新其他缺口的期限。当前缺口未补齐时增加一人、再次刷新或重试都不能延长倒计时。

实施时间约束：征集截止 < 活动开始 < 活动结束；普通报名及候补递补截止位于征集截止至活动开始之间。补齐阶段允许个人报名，优先递补仍有效的候补；普通报名截止不阻止明确的人数补齐入口。候补过了递补截止不自动入选，可自行在人数补齐时报名。补齐期限为故障开始时间加预设时长与活动开始二者较早值，不能自动延后活动。已到期缺口先取消，不能由截止后报名救活。

所有规则采用Europe/Amsterdam显示，持久保存UTC毫秒；禁止含糊的夏令时转换。发布后最低人数和其他规则锁定；唯一例外是发布者可在报名截止前执行 `raise_capacity`，把人数上限提高到不超过 100 的整数。扩至 9 人及以上会强制启用场地条件；已成行或补齐中的活动在场地规则生效时，现有已批准场地容量必须覆盖新上限。有候补且递补截止已过时拒绝扩容；成功后保留 `{before, after}` 回执、发送 `capacity_expanded` 通知，并复用原 FIFO 候补邀请或转正流程。description文字更正留记录。取消及旧征集重新发布时需要成员重新报名。

本地首版对退出期限的实施解释：依据后续“原最低人数保持不变，退出先递补再倒计时”的简化要求，没有增加独立的退出锁定期限；正式报名者可在开始前退出。早期需求D04b/R01仍记有发布者配置退出期限，这一差异需在产品验收时明确，不能算作已获新的逐字段确认。活动进行中允许发布者紧急取消、候补本人离开队列，其他参与变更关闭；终态只读。介绍修改回执保存更正前后全文及时间。

## 角色与公开数据

任意验证邮箱用户可发布；发布人和获批协办可审资源/分享。仅发布人批准协办、撤销协办、人工取消。现场负责人申请由管理者确认，角色兼任是否满足条件依据规则。退出角色立即撤权限，不删除历史审核。普通成员只能执行本人操作。

API明确构造公开投影，不返回完整内部JSON。访客见规则、统计及自愿公开昵称；邮箱不公开。详情中的申请只对本人及管理者可见，已批准的场地/分享可显示公开摘要。私有场地地址仅正式报名者及管理者可见，候补和退出者没有访问权限。邮件只发送对应人的数据，禁止全员to列表。

## AI、邮件、验证

AI读取公开活动状态及本人的报名，返回文字或受限的join/leave建议。建议持久化且绑定用户、活动版本、动作、过期时间；点击确认后重新验证会话、版本和规则。模型不能自行执行，失败时普通按钮照常可用。模型不可访问成员邮件、任意SQL或管理工具。

邮件由Brevo发送，D1 outbox保存待发/发送中/已发送/失败状态；并发认领、租约恢复、指数退避，OTP与批量通知共用受限日预算并预留OTP余量。提供商接收不能当作已读。生产未配置邮件时登录明确不可用；本地仅loopback且development模式可显示测试验证码，不打印日志。生产API不会返回测试码。

具体认证失败限制、通知重试参数在实现与测试清单中维护。不开通付费，不改域名，不迁移旧数据。运行开发部署前先确认D1绑定及secret配置，本地测试使用隔离数据库和假邮件。
